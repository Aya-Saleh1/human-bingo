# Human Bingo — لعبة جماعية أونلاين

النسخة جاهزة للتجربة باستخدام Node.js، بدون حسابات للاعبين أو قاعدة بيانات خارجية. كل لاعب يفتح الرابط من هاتفه، يختار اسمًا فريدًا، وتظهر له بطاقة Bingo. تحديثات اللاعبين والبطاقات تصل مباشرة إلى بقية اللاعبين.

## 1. رفع اللعبة على الإنترنت (Render)

**هذه لعبة Node.js، وليست موقع HTML ثابتًا.** لا تستخدم Netlify Drop أو GitHub Pages لتشغيل هذا المشروع كاملًا.

1. فك ضغط ملف ZIP.
2. افتح GitHub وأنشئ Repository جديدًا، مثل `human-bingo`.
3. ارفع **محتويات مجلد اللعبة** إلى جذر Repository، وليس ملف ZIP نفسه. يجب أن ترى `server.js` و`package.json` و`public/` في المستوى الرئيسي.
4. افتح [render.com](https://render.com) وسجّل الدخول بحساب GitHub.
5. اختر **New → Web Service**، واربط الـ Repository.
6. اضبط الإعدادات:
   - **Language / Runtime:** `Node`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** `Free` (للتجارب فقط)
   - **Health Check Path** (إن ظهر): `/health`
7. في **Environment Variables** أضف المتغير `HOST_KEY`، بقيمة كلمة سر **طويلة وصعبة التخمين** من اختيارك؛ لا تضعها داخل الكود أو GitHub.
8. اضغط **Deploy Web Service**، وتابع الـ Logs حتى يظهر أن التطبيق يعمل.
9. رابط اللاعبين سيكون مثل: `https://your-name.onrender.com/`.
10. رابط مدير اللعبة فقط: `https://your-name.onrender.com/?host=YOUR_SECRET`، مع استبدال `YOUR_SECRET` بقيمة `HOST_KEY` التي أدخلتها. **لا تشارك هذا الرابط**.

**مهم:** خدمة Render المجانية تنام بعد 15 دقيقة من عدم النشاط. والأهم أن الملفات المحلية **غير دائمة** على الخطة المجانية؛ لذلك قد تختفي أسماء اللاعبين والبطاقات والنتائج عند النوم/إعادة التشغيل أو إعادة النشر. هذا الخيار مناسب للتجربة القصيرة، وليس لحدث مهم يتطلب حفظ التقدم. للاستعمال المستمر استخدم تخزينًا دائمًا (قاعدة بيانات) واستضافة ملائمة.

يوجد ملف `render.yaml` اختياري يمكن استخدامه إن اخترت **New → Blueprint** بدل Web Service؛ سيطلب Render كلمة سر `HOST_KEY` عند إنشاء الخدمة.

## 2. تشغيل اللعبة محليًا

يتطلب **Node.js 18 أو أحدث**. افتح Terminal داخل المجلد:

```bash
npm start
```

ثم افتح `http://localhost:3000/`.

لتشغيل أدوات المدير محليًا، عيّن `HOST_KEY` قبل بدء السيرفر:

- **PowerShell:** `$env:HOST_KEY="a-long-secret"; npm start`
- **Windows CMD:** `set HOST_KEY=a-long-secret && npm start`
- **macOS/Linux:** `HOST_KEY=a-long-secret npm start`

رابط المدير محليًا: `http://localhost:3000/?host=a-long-secret`

## 3. ملاحظات اللعب والتقنية

- المستخدمون يسجلون باسم مستعار، بدون حساب أو كلمة مرور؛ هوية المتصفح محفوظة في Cookie محمية بتوقيع. الاحتفاظ بنفس المتصفح يحافظ عادةً على الهوية ما دام السيرفر يحتفظ ببياناته ويظل السر ثابتًا.
- لكل لاعب بطاقة عند الانضمام، ويمكن طلب بطاقة إضافية لإهدائها. كل لاعب يحتفظ ببطاقة واحدة على الأقل.
- السيرفر يفحص صلاحية تعديل البطاقات، يمنع تكرار نفس اللاعب في البطاقة الواحدة، يمنع تقديم هدايا عكسية بين نفس الطرفين، ويتحقق من الفوز قبل قبول المطالبة.
- أدوات مدير اللعبة تتطلب `HOST_KEY`. زر New Game يزيل التأشيرات والمطالبات، **ولا يمسح أسماء اللاعبين أو سجلات الهدايا**.
- ميزة الكاميرا تعمل عادةً عبر HTTPS على الهواتف، وتحتاج إذن الوصول إلى الكاميرا. يمكن بدلًا منها إدخال اسم المستخدم يدويًا.
- توليد QR ومسحه يعتمدان على مكتبتين عبر CDN؛ يلزم اتصال الإنترنت لتحميلهما.
- جميع اللاعبين في **غرفة واحدة مشتركة**. لا يوجد نظام غرف منفصلة أو حسابات أو لوحة إدارة متقدمة.
- لا تنشر `data.json` على GitHub؛ هذا الملف مستبعد افتراضيًا عبر `.gitignore`.
